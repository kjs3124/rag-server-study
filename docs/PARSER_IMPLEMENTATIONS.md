# 파서 구현 참조 문서

RAG 시스템에서 구현된 모든 문서 파서의 기술 사양을 제공합니다.

## 개요

시스템은 팩토리 패턴을 사용하여 10개의 전문화된 파서를 구현하며, 각각은 특정 파일 형식에 최적화되어 있습니다. 모든 파서는 `BaseDocumentParser`를 상속하고, 각 문서 타입에 최적화된 LangChain 전용 청커(HTMLHeaderTextSplitter, CSVLoader)를 우선 사용하며, 폴백으로 `RecursiveCharacterTextSplitter`를 사용합니다.

## 지원 파일 형식

| 파서 | 확장자 | 주 라이브러리 | 보조 라이브러리 | 청킹 방식 |
|------|---------|---------------|---------------|-----------|
| PDFParser | .pdf | PyMuPDF 1.26.3 | pdfplumber 0.12.1 | LangChain |
| DOCXParser | .docx, .doc | python-docx 1.2.0 | - | LangChain |
| ExcelParser | .xlsx, .xls | openpyxl 3.1.5 | - | 커스텀 + 시트 기반 |
| PPTXParser | .pptx, .ppt | python-pptx 1.0.2 | - | LangChain |
| HTMLParser | .html, .htm | HTMLHeaderTextSplitter | trafilatura 2.0.0 | 구조적 + 폴백 |
| MarkdownParser | .md, .markdown | markdown 3.8.2 | - | LangChain |
| TXTParser | .txt, .text | chardet 5.2.0 | - | LangChain |
| CSVParser | .csv | CSVLoader | polars 1.32.3 | 전용 + 폴백 |
| WebCrawlerParser | URL | HTMLHeaderTextSplitter | trafilatura 2.0.0 | 구조적 + 폴백 |

## 파서 구현 세부사항

### PDFParser

**주 라이브러리**: PyMuPDF (fitz)

- **기능**: 빠른 텍스트 추출, 메타데이터 보존, 페이지 단위 처리
- **폴백**: 테이블 인식을 위한 pdfplumber
- **아키텍처**: 속도와 정확성을 결합한 하이브리드 접근
- **청킹**: 문서 인식 구분자를 사용한 LangChain
- **메타데이터**: PDF 속성, 페이지 번호, 생성 날짜

**기술적 특징**:

- 메모리 효율적인 페이지별 처리
- 문서 구조와 포맷 보존
- 텍스트와 테이블 콘텐츠 모두 처리

### DOCXParser

**주 라이브러리**: python-docx

- **기능**: 네이티브 DOCX 형식 지원, 스타일 감지, 메타데이터 추출
- **처리 능력**: 문단 단위 파싱, 제목 감지, 문서 속성
- **청킹**: 제목 인식 구분자를 사용한 LangChain
- **메타데이터**: 문서 속성 (작성자, 제목, 생성 날짜)

**기술적 특징**:

- 변환 없는 직접 XML 파싱
- 문서 계층 구조와 스타일 보존
- 문서 메타데이터에서 핵심 속성 추출

### ExcelParser

**주 라이브러리**: openpyxl

- **기능**: 다중 시트 지원, 셀 수준 접근, 수식 계산
- **처리**: 헤더 감지를 통한 시트별 반복 처리
- **청킹**: 구성 가능한 행 제한이 있는 커스텀 구현
- **메타데이터**: 시트 개수, 차원, 셀 포맷팅

**기술적 특징**:

- 메모리 효율성을 위한 읽기 전용 모드
- 수식 계산을 위한 데이터 전용 모드
- 병합 셀과 포맷팅 처리

### PPTXParser

**주 라이브러리**: python-pptx

- **기능**: 슬라이드 단위 파싱, 도형 텍스트 추출, 레이아웃 감지
- **처리**: 텍스트 프레임 추출을 통한 순차적 슬라이드 반복
- **청킹**: 슬라이드 인식 구분자를 사용한 LangChain
- **메타데이터**: 슬라이드 개수, 레이아웃 정보, 도형 통계

**기술적 특징**:

- 슬라이드 구조와 번호 보존
- 모든 도형 유형에서 텍스트 추출
- 프레젠테이션 흐름 유지

### HTMLParser

**주 라이브러리**: HTMLHeaderTextSplitter

- **기능**: HTML 헤더 기반 구조적 청킹, 문서 계층 구조 보존
- **폴백**: trafilatura를 사용한 고품질 텍스트 추출 + markdownify 구조화
- **처리**: 1차 구조적 청킹 → 2차 일반 텍스트 청킹 (폴백)
- **청킹**: HTMLHeaderTextSplitter 우선, LangChain 폴백
- **메타데이터**: 헤더 구조 정보, 콘텐츠 품질 지표, 파서 유형

**기술적 특징**:

- H1/H2/H3 헤더 기반 의미적 문서 분할
- 구조적 청킹 실패 시 trafilatura + markdownify 폴백
- 문서의 계층 구조와 헤더 메타데이터 보존
- 웹 콘텐츠와 로컬 HTML 파일 모두 최적화

### MarkdownParser

**주 라이브러리**: markdown

- **기능**: 확장 지원 (toc, tables, fenced_code), HTML 변환
- **처리**: 제목 계층을 통한 구조 인식 파싱
- **청킹**: 마크다운 전용 구분자를 사용한 LangChain
- **메타데이터**: 구조 지표 (제목, 코드 블록, 테이블)

**기술적 특징**:

- 마크다운 문법과 구조 보존
- GitHub Flavored Markdown 확장 지원
- 계층적 문서 구성 유지

### TXTParser

**주 라이브러리**: chardet

- **기능**: 자동 인코딩 감지, 다국어 지원
- **처리**: 폴백 처리를 통한 인코딩 인식 파일 읽기
- **청킹**: 텍스트 최적화 구분자를 사용한 LangChain
- **메타데이터**: 인코딩 정보, 문자 통계

**기술적 특징**:

- 다중 문자 인코딩 자동 처리
- 한국어 및 멀티바이트 문자 최적화
- 인코딩 감지 신뢰도 점수 제공

### CSVParser

**주 라이브러리**: CSVLoader (LangChain)

- **기능**: CSV 전용 문서 로더, 행별 청킹, 메타데이터 보존
- **폴백**: polars를 사용한 고성능 데이터 처리 + LangChain 청킹
- **처리**: 1차 CSVLoader 직접 청킹 → 2차 polars + LangChain 청킹 (폴백)
- **청킹**: CSVLoader 우선, polars + LangChain 폴백
- **메타데이터**: 행/열 정보, 인코딩 상태, 파서 유형

**기술적 특징**:

- CSV 파일의 각 행을 개별 문서 청크로 처리
- CSVLoader 실패 시 polars의 고성능 DataFrame 처리 폴백
- 자동 인코딩 감지 (chardet) 및 한국어 최적화
- 구성 가능한 CSV 구분자 및 메타데이터 보존

### WebCrawlerParser

**주 라이브러리**: HTMLHeaderTextSplitter

- **기능**: HTML 헤더 기반 구조적 웹 콘텐츠 청킹, 링크 발견, 깊이 제어
- **폴백**: trafilatura를 사용한 고품질 텍스트 추출 + 커스텀 청킹
- **처리**: 1차 구조적 청킹 → 2차 trafilatura 텍스트 청킹 → 3차 requests + BeautifulSoup 폴백
- **청킹**: HTMLHeaderTextSplitter 우선, trafilatura + 커스텀 청킹 폴백
- **메타데이터**: 헤더 구조 정보, 크롤링 통계, URL 추적, 깊이 정보

**기술적 특징**:

- 웹페이지의 H1/H2/H3 헤더 기반 의미적 콘텐츠 분할
- 구조적 청킹 실패 시 trafilatura의 고품질 텍스트 추출 폴백
- nest-asyncio 호환성을 통한 비동기 크롤링 처리
- 도메인 기반 크롤링 제한 및 요청 간 구성 가능한 지연

## 라이브러리 비교

### PDF 처리 라이브러리

#### PyMuPDF (주요)

- 성능: 고속 텍스트 추출
- 메모리 사용량: 효율적인 페이지 단위 처리  
- 기능: 포괄적인 PDF 조작
- 형식 지원: 모든 PDF 버전

#### pdfplumber (폴백)

- 전문 분야: 테이블 구조 인식
- 정확도: 정밀한 텍스트 위치 지정
- 사용 사례: 복잡한 문서 레이아웃
- 성능: 보통 속도, 높은 정확도

### 웹 콘텐츠 추출

#### HTMLHeaderTextSplitter (주요)

- 목적: HTML 헤더 기반 구조적 문서 분할
- 기능: H1/H2/H3 헤더 인식 자동 청킹
- 성능: 문서 구조 보존에 최적화
- 메타데이터: 헤더 계층 구조 정보 보존

#### trafilatura (폴백)

- 목적: 웹 페이지에서 깨끗한 콘텐츠 추출
- 기능: 자동 노이즈 제거, 주요 콘텐츠 감지
- 성능: 콘텐츠 품질에 최적화
- 언어 지원: 다국어 텍스트 추출

#### beautifulsoup4 (최종 폴백)

- 목적: 일반적인 HTML 파싱 및 조작
- 기능: 완전한 DOM 접근, 유연한 파싱
- 사용 사례: 링크 추출, 구조 분석
- 신뢰성: 범용 HTML 호환성

### 데이터 처리 라이브러리

**CSVLoader (CSV 처리 주요)**

- 목적: CSV 파일의 각 행을 개별 문서로 청킹
- 기능: 자동 메타데이터 보존, 구성 가능한 구분자
- 성능: LangChain 생태계 최적화
- 특징: 행별 직접 청킹, 추가 변환 단계 불필요

**polars (CSV 처리 폴백)**

- 백엔드: Rust 기반 고성능 엔진
- 메모리: 지연 평가, 메모리 효율적
- 성능: 대용량 데이터셋에서 pandas보다 빠름
- 기능: 자동 타입 추론, 멀티스레드 처리

**openpyxl (Excel 처리)**

- 형식 지원: XLSX, XLSM 네이티브 형식 지원
- 기능: 셀 단위 접근, 수식 계산
- 메모리: 대용량 스프레드시트에 최적화
- 호환성: Microsoft Excel 형식 준수

## 공통 기능

모든 파서가 구현하는 기능:

### 기본 기능

- 추상 기본 클래스 상속 (`BaseDocumentParser`)
- 표준화된 메타데이터 추출
- 일관된 청크 ID 생성
- 오류 처리 및 로깅

### LangChain 통합

#### 전용 청커 (우선 사용)
- **HTMLHeaderTextSplitter**: HTML/웹 콘텐츠의 헤더 기반 구조적 분할
- **CSVLoader**: CSV 파일의 행별 직접 청킹 및 메타데이터 보존

#### 범용 청커 (폴백)
- 일관된 청킹을 위한 `RecursiveCharacterTextSplitter`
- 문서 타입별 사용자 정의 가능한 구분자
- 구성 가능한 청크 크기 및 중첩
- 청크 내 메타데이터 보존

### 인코딩 지원

- `chardet`을 사용한 자동 인코딩 감지
- 폴백 처리가 있는 UTF-8 기본값
- 다국어 문자 지원
- 한국어 최적화

## 아키텍처 패턴

### 팩토리 패턴

- 파일 확장자 기반 중앙 집중식 파서 선택
- 알 수 없는 형식에 대한 TXTParser 폴백
- 웹 크롤링을 위한 URL 감지

### 하이브리드 처리

- 핵심 기능을 위한 주요 라이브러리
- 전문 기능을 위한 보조 라이브러리
- 우아한 폴백 메커니즘

### 청킹 전략

#### 구조적 청킹 (우선)
- **HTML/웹**: HTMLHeaderTextSplitter를 사용한 헤더 기반 의미적 분할
- **CSV**: CSVLoader를 사용한 행별 직접 청킹
- **문서 구조 보존**: 원본 문서의 계층 구조 및 메타데이터 유지

#### 텍스트 청킹 (폴백)
- 문서 타입 인식 구분자 (RecursiveCharacterTextSplitter)
- 계층적 분할 (섹션 → 문단 → 문장 → 단어 → 문자)
- 청크 간 메타데이터 보존
- 구성 가능한 크기 제한 및 중첩

#### 커스텀 청킹 (특수 형식)
- **Excel**: 시트별 처리 및 행 제한 기반 청킹
- **웹 크롤링**: 구조적 청킹 실패 시 단어 기반 분할 폴백

## 최근 개선사항 (2024)

### LangChain 전용 청커 통합

#### HTMLHeaderTextSplitter 적용
- **적용 파서**: HTMLParser, WebCrawlerParser
- **개선 효과**: HTML 문서의 헤더 구조 기반 의미적 청킹
- **폴백 전략**: 구조적 청킹 실패 시 기존 trafilatura + LangChain 방식 사용
- **메타데이터**: 헤더 계층 구조 정보 보존

#### CSVLoader 적용
- **적용 파서**: CSVParser
- **개선 효과**: CSV 행별 직접 청킹, 추가 변환 단계 불필요
- **폴백 전략**: CSVLoader 실패 시 polars + LangChain 방식 사용
- **메타데이터**: 각 행의 원본 CSV 메타데이터 보존

### 타입 안전성 강화
- **mypy 준수**: 모든 파서에서 엄격한 타입 검사 통과
- **조건부 import**: Any 타입 어노테이션을 사용한 안전한 라이브러리 import
- **타입 호환성**: import alias 패턴으로 타입 재정의 오류 해결

### 코드 품질 개선
- **미사용 코드 정리**: 모든 파서에서 미사용 import 및 변수 제거
- **Import 최적화**: 필요한 타입 import만 유지
- **일관된 패턴**: 모든 파서에서 동일한 조건부 import 패턴 적용

### 성능 최적화
- **구조적 청킹 우선**: 문서 구조를 보존하는 청킹 방식 우선 사용
- **효율적인 폴백**: 전용 청커 실패 시에만 범용 청커 사용
- **메타데이터 향상**: 각 청킹 방식별 상세한 메타데이터 제공
